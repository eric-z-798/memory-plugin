## 本次修复

生产代码仅改 `aigc/store.py`，移除全行 seq 正则，分成两个明确路径：

1. **完整记录读取**：先用标准库 JSON 解码完整一行，通过 `object_pairs_hook` 拒绝重复对象键，再验证解码对象的顶层 `seq`、消息字段和顺序。嵌套字典、数组和正文中的 `seq` 不参与顶层身份判定。Store 正常写出的有效记录不被隔离，id、seq、正文和元数据保持一致。
2. **真正畸形行恢复**：仅在完整解码或字段验证失败后，逐个读取根对象的键和值。`JSONDecoder.raw_decode` 消费整个嵌套值、数组和转义字符串；键必须是 JSON 字符串，值必须有完整边界。遇到结构错误即停止，不跨过坏结构扫描后文，也不把 `123xyz` 或 `123.4` 的整数前缀作为序号。此路径始终隔离原字节，不将解码替换字符用于恢复聊天正文。

恢复解码器以字符串令牌保存整数，不转换数千位数字；只对结构上确认是根对象 `seq` 的正整数令牌应用既有精确范围检查。嵌套巨大数字可被完整跳过，不能误判为消息序号，也不会阻挡后面可辨认的根序号。没有提高或关闭全局整数转换限制。

**重复键边界**：顶层或嵌套重复对象键都视为有歧义的行，原字节隔离，不默认采用最后值。恢复路径只保留结构可辨认的所有顶层seq候选的最大高水位；同名嵌套字段仍不参与。例：顶层seq99、seq1重复时，恢复提示从100起，不会复用1或99。转义后的同名键也按重复键处理。该歧义行处理是本次需要复审的兼容边界；Store 本身从字典编码出的正常记录不会包含重复键。

每条坏行的 `recovery.quarantined_records` 记录原行号、隔离原因及 `reserved_sequences`。原有 `ignored_sequences` 只记录确实识别出的超范围**顶层**序号，原字节备份和隔离保持不变。无法越过的坏结构后方不猜测序号；`reserved_sequences=[]` 表示未可靠辨认身份，不宣称已恢复无法解析的内容。
