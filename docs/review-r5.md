# 令牌恢复与追加写入结果核验

基线：`c4a0b0b778b21874219c0adc362944cb7d381a39`。修复分支：`fix/claude-r1-20261104`。

## 改动

- 同文档启动链接的 `hashchange` 会保存当前草稿、取消旧页面请求并重新加载。新文档在首次 API 请求前消费新令牌、清除片段；sessionStorage 被禁用时仍可工作。旧页面的 API/导出结果不会更新界面。已经到达服务器的请求不能由页面取消撤销。
- 消息追加发生 OSError 时，清空缓存并只读核验完整记录（全字段、id、seq）。不在核验阶段修复文件、再次追加或假装 fsync 成功。`MessageAppendError` 保留原异常及读回结果：完整可读、不完整、无法核实。
- 完整回复可读时不再提供补答，也不再次调用模型；警告明确标明耐久性未知、原异常和记录身份。看板、候选记忆和已读进度不因此推进。当前回合不自动重试。重启后完整回复仍清除旧补答状态。
- 完整用户消息可读但同步失败时，HTTP 202 明确告知讨论未启动、耐久性未知；界面显示警告并清除未再次编辑的已发送草稿。用户可核对后继续讨论，不应重发。无法读回时 HTTP 503 明确 `retry_safe=false`，要求核对原文件；不声称保存成功。
- 不完整写入继续保留原失败与恢复路径。恢复前原字节不被此次核验改写。无法核实的回复不会引导自动补答；若连警告也无法写入，只能保留控制台异常，不能承诺跨断电持久性。
