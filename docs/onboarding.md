# 安装、代理与账号登录

0.4.0 新增安装与登录引导，继续使用三家已有账号，不新增模型 API Key。

## 首次准备

1. 在需要运行三家 CLI 的电脑上安装 Python 3.8+，解压本工具。Windows 运行 `start-windows.bat`；macOS/Linux 运行 `./start-linux.sh`。`--demo` 仅供体验，不执行安装、登录或网络探测。
2. 以默认本机地址打开网页，点侧栏「安装与登录」。手机访问另一台服务器时，CLI 仍运行在服务器上，不能通过此入口安装到手机。
3. 选择网络方式并保存。如果网络已经可用，保留默认；使用本机代理软件时，填写其 HTTP/HTTPS 监听地址，例如 `http://127.0.0.1:7890`，端口以你自己的代理软件为准。工具不会自动安装代理软件或扫描端口。
4. 可以先点网站连通检测。它仅访问固定官方首页，不调用模型；收到 403 等 HTTP 响应也只能说明网站或代理返回了响应，不能证明登录或模型服务可用。
5. 在成员卡片点「一键安装并登录」。本机终端会打开，显示官方安装与登录流程；已找到 CLI 就跳过安装。也可单独安装或登录。
6. 在官方浏览器页面完成授权。Claude 使用 `claude auth login`，Codex 使用 `codex login`，Gemini 使用 `agy` 的交互登录。agy 首次运行可能询问主题、工作区信任等；完成登录后输入 `/exit` 结束引导。不要在群聊中粘贴密码或授权码。
7. 回网页刷新检测。安装流程完成不等于登录成功。Claude/Codex 可读取官方状态命令；Gemini 需在官方终端确认个人账号，工具保持“待确认”。如需验证实际生成，可显式点击「测试连通」，该操作可能消耗额度。

官方来源见 [兼容性核验](onboarding-compatibility.md)。安装脚本可能更新用户 PATH、shell 配置或 CLI 文件；工具不会额外添加 sudo 或自动提权。

## 三种网络方式

| 方式 | 本工具的行为 |
| --- | --- |
| 继承启动环境 | 保留代理环境变量，适合启动本工具的终端已配置网络的情况 |
| 直连 | 清除子进程中的 HTTP/HTTPS/ALL_PROXY 环境变量 |
| 自定义 | 对安装、登录、检测、聊天及额度查询的子进程设置一致的 HTTP/HTTPS 代理环境变量 |

不修改操作系统全局代理或 TLS 校验。部分 CLI 可能自行优先读取系统/PAC 策略，因此环境配置不能保证覆盖其所有网络路径。浏览器授权页面使用浏览器自身的网络配置。localhost、127.0.0.1、::1 始终加入代理绕过列表，避免本地授权回调误走代理；原有 NO_PROXY 项也保留。

macOS 原生 Terminal 的新窗口可能使用自己的环境，未必继承启动网页服务的终端环境。需要一致的代理地址时，请在引导里选择自定义；该配置会显式传给 worker。自定义代理仅接受带明确端口的 HTTP/HTTPS URL，不保存用户名或密码，不支持 SOCKS。需要代理认证或企业 CA 的场景，仍应按官方 CLI 指引在本机终端准备。

保存后，新安装/登录流程使用新设置。正在运行的进程不会被改动；讨论轮次中的模型调用沿用该轮设置快照。代理变化会使 CLI 检测及额度缓存重新计算。

## 任务状态与取消

每个成员同时只能有一个安装/登录流程。网页保存的是 launching、running、completed、failed、cancelled 等流程状态，不收集终端输出、密码、OAuth URL、验证码或登录令牌。官方 CLI 自己保存登录凭据。

完成状态仅表示官方命令成功退出，需刷新登录检测；关闭终端、取消浏览器授权或安装失败不会被假称为登录成功。关闭并重新打开引导可以找回仍在运行的任务。点停止会请求终止本次流程，已经安装的软件或官方已保存的登录状态不会因此回滚。

本机辅助终端支持 Windows、macOS 及装有常见桌面终端的 Linux。无图形桌面、未找到终端或远程访问模式会显示原因，并保留官方命令供复制到运行 CLI 的主机执行。原生安装/登录、代理修改与网络探测接口要求本机模式和 loopback 访问；没有为了“一键”开放远程终端。

## 接口与存储

写接口沿用 `X-AIGC: 1` 和既有访问认证；动作仅接受预定义成员与 install/login/setup，不接受网页提交的任意 shell 命令或下载 URL。

- `GET /api/setup`：平台、启动能力、官方命令与正在执行的任务；不启动安装或登录。
- `POST /api/setup/proxy`：`{proxy: {mode, url}}`；只更新网络配置。
- `POST /api/setup/:member/network`：检查固定官方站点；演示模式不联网。
- `POST /api/setup/:member/start`：`{action: "install" | "login" | "setup"}`；返回 `{job}`。
- `GET /api/setup/jobs/:id`：只返回流程状态；ID 为 32 位十六进制字符串。
- `POST /api/setup/jobs/:id/cancel`：请求停止，不回滚安装。

代理配置保存在数据目录的 `settings.json`；任务元数据位于 `setup-jobs/`。任务配置只保留动作、CLI 路径、无凭据的代理设置等必要字段，不保存完整环境。Unix 设置私有文件权限；Windows 继承数据目录访问权限。

本版使用模拟安装器、假进程和浏览器接口夹具验证流程，未实际安装三家 CLI、登录真实账号或验证三个操作系统的真实终端。用户设备上的官方安装器、系统权限、网络与浏览器回调仍需实机核验。
